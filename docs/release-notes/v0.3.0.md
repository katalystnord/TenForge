TenForge 0.3.0: a test's results carried into the tools around it,
FreeCAD, CalculiX, ParaView, PyVista and Platform MaterialDigital, by
files you hand across.

- **FreeCAD and CalculiX.** File > Export for FreeCAD and CalculiX writes
  a FreeCAD 1.x material card (`.FCMat`) with what the test measured
  (Young's modulus, yield and tensile strength, or a compressive
  strength), the hardening curve as FreeCAD FEM's Yield Points, and the
  same curve as a CalculiX `*PLASTIC` block. The hardening curve is true
  stress against true plastic strain from initial yield (ReL, else
  Rp0.2) to the maximum force; necking is left out and the stress never
  falls. Poisson's ratio and density are not measured by a tensile test
  and are not written: the card says to enter them.
- **ParaView and PyVista.** File > Export curve for ParaView writes the
  analysed curve as a `.vtp` file, its results riding along as field data;
  every saved record now holds it too, as `results/curve.vtp`. Plot it in
  ParaView's Line Chart View (X `strain_percent`, Y `stress_MPa`).
  `TenForgeRecordReader.py`, attached to this release, is a ParaView
  reader plugin: load it once and File > Open a record's `manifest.tfrec`
  to get its curve with the specimen, procedure and conformity. Like
  TenForge, it refuses a record whose curve changed after it was written.
  `tools/recipes/pyvista_curve.py` in the sources shows the PyVista side.
- **Platform MaterialDigital.** File > Export for Platform MaterialDigital
  writes a tensile test as JSON-LD in the PMD Core Ontology 3.1.2 and the
  Tensile Test Ontology 3.0.0, with QUDT units.
- **Reference curves.** File > Add reference curve (PlotTracer) draws a
  curve digitised from a paper beside the test's own, dashed. You say
  which column is strain and which is stress, and their units; TenForge
  proposes them from the labels. A reference never enters the analysis;
  the record keeps its file byte for byte.
- `tf-analyse` gains --freecad, --vtp, --pmd and --record.

Checked against the programs themselves (docs/validation/phase-4.md):
FreeCAD 1.1.4 loads the card, and CalculiX solves FreeCAD's own nonlinear
example on the exported yield points; ParaView 6.1.0 reads the curve and
opens records with the plugin; PyVista 0.49 reads the curve and its
results; every ontology term in the JSON-LD is in the released ontology
files. The exports are specified in docs/specs/exports-v1.md, still a
draft for review.

**Every result is still "aligned with" its standard, not "to" it**: the
procedures' parameters come from public sources and stay unconfirmed until
checked against the purchased standards. Each export says so inside
itself.

The AppImage is for x86_64 Linux, built on Ubuntu 26.04, as before. Files
only, one test at a time; running a machine comes in 0.4. The manual is
in docs/manual/.
